# XTree Gram — iOS build

Собирает **unsigned `.ipa`** клиента XTree Gram из upstream Telegram-iOS прямо в GitHub Actions.
Подписи нет намеренно: `.ipa` подписывается при установке вашим Apple ID (Sideloadly / AltStore / 3uTools).

Готовый клиент подключается **только к нашему серверу** (`2.27.200.203:2398`, DC 2).

## Скачать готовый `.ipa`

**[Xtreegram-unsigned-12.9.2-build14.ipa](https://github.com/exepka-beep/xtreegram-ios-build/releases/download/v12.9.2/Xtreegram-unsigned-12.9.2-build14.ipa)** (71.2 МБ, arm64, iOS 13+)
· [страница релиза](https://github.com/exepka-beep/xtreegram-ios-build/releases/tag/v12.9.2)

Сборка #14 от 6 октября 2026 (`sha256 401d39b6…4dbba`, `CFBundleVersion 934474`). В ней закрыты
четыре дефекта самосборки: App Group, RSA-ключ сервера, падение в декодере PNG и падение на
OpenGL-интро первого экрана (подробности ниже). Предыдущие сборки удалены — они зависали на
чёрном экране либо вылетали через 15–40 мс после запуска.

`CFBundleVersion` этой сборки начинается с `9` намеренно: upstream выводит номер сборки из
количества коммитов, поэтому все сборки одного коммита носили один и тот же номер `34474`,
и на телефоне нельзя было отличить установленную версию от предыдущей. Проверить, что
поставилась именно #14, можно в «Настройки → Основные → Хранилище iPhone»: должно быть **934474**.

Ссылка работает без входа в аккаунт. Вложения релиза не истекают, в отличие от артефактов Actions
(те живут 90 дней и требуют авторизации).

Установка: Sideloadly или AltStore → подключить iPhone → перетащить `.ipa` → обычный Apple ID →
на телефоне доверять профилю в «Настройки → Основные → VPN и управление устройством».
Бесплатный Apple ID даёт подпись на **7 дней**.


## Почему патч, а не форк

Telegram-iOS — это Bazel-проект на десятки тысяч файлов. Держать форк дорого: каждая правка
превращается в конфликт при обновлении. Здесь лежит только дифф, а сам исходник клонируется
на запинованном коммите — поэтому сборка воспроизводима, а обновление upstream это одна строка.

| Файл | Что делает |
| --- | --- |
| `.github/workflows/build-unsigned-ipa.yml` | Весь конвейер: клон upstream → патч → ключ → Xcode → сборка → чистка → zip |
| `scripts/apply_mods.sh` | Накладывает патч (сначала `--check`, чтобы устаревший патч падал громко) и запускает фикс App Group |
| `scripts/apply_rsa_key.py` | Вшивает наш серверный публичный ключ в `defaultPublicKeys()` |
| `scripts/apply_app_group_fallback.py` | Учит клиент работать без App Group (его не даёт бесплатный Apple ID) |
| `scripts/slim_ipa.sh` | Выкидывает лишние расширения, локали, символы |
| `patches/0001-xtreegram-branding-and-server.patch` | Брендинг + адрес сервера |
| `config/server-rsa-public.pem` | Публичный RSA-ключ нашего сервера |

## Четыре подводных камня самосборки

Их нет в обычной сборке Telegram, потому что она ходит на настоящие ДЦ Telegram со штатными ключами.
Первые два проявляются **чёрным экраном при запуске**, третий и четвёртый — **вылетом через 15–40 мс
после запуска**.

**1. App Group.** `AppDelegate` берёт общий контейнер `group.<bundle id>`. Для него нужно право
`com.apple.security.application-groups`, которого у бесплатного Apple ID нет — а в неподписанном IPA
прав нет вообще, поэтому Sideloadly их и не сохраняет. Дальше срабатывает `guard let appGroupUrl …
else { алерт «Error 2»; return true }`, алерт показать некуда (root-контроллера ещё нет), и приложение
остаётся с пустым окном. Фикс — фолбэк в собственный Documents.

**2. RSA-ключ сервера.** MTProto-рукопожатие проходит только если клиент знает ключ, чей отпечаток
сервер объявляет в `resPQ`. У нас свой ключ → `0x9dbe5a4c45febeff`, у Telegram штатные →
`0xb25898df208d2603` и `0xd09d1d85de64fd85`. Без подмены `selectPublicKey()` возвращает nil и логин
не проходит никогда.

Если на сервере пересоздать RSA-ключ (`TELESRV_RSA_IDENTITY_MODE=generated` или удалить файл ключа),
отпечаток изменится — обнови `config/server-rsa-public.pem` и пересобери, иначе **все** клиенты
перестанут подключаться.

**3. Декодер PNG в ImageIO на первом экране.** Как только приложение проходит дальше старта, первое,
что оно делает, — строит интро-анимацию (`RMIntroViewController`), а та грузит 23 PNG-спрайта
через `[UIImage imageNamed:]` из `setup_texture()`. На iPhone 11 под iOS 26.5 (23F77) этот путь
фатален: главный поток прыгает в неразмеченную память внутри `__PNGReadPlugin::InitializePluginData`
и приложение умирает через 39.9 мс после запуска, каждый раз. Сами PNG при этом целые — CRC сходятся,
таблицы смещений `iDOT` согласованы, Apple-овская `CgBI`-оптимизация на месте (её нет только у
палитрового `telegram_plane1@2x.png`, и это тоже нормально — pngcrush палитровые не трогает).
Поскольку интро — чистая косметика, `scripts/apply_intro_texture_guard.py` отключает загрузку текстур:
`setup_texture()` сразу возвращает `-1` (ровно то, что upstream сам отдаёт при неудачной загрузке),
интро остаётся, но рисует без спрайтов. Парный `scripts/apply_splash_auto_advance.py` не даёт сплэшу
стать тупиком: если кнопку «Start Messaging» не нажали, логин стартует сам через 3 секунды.

**4. OpenGL-интро и `strip -x`.** После фикса #3 краш не исчез, а переехал: через 14.4 мс после
запуска главный поток снова прыгал в неразмеченную память, но уже внутри UIKit-отрисовки, а не в
декодере PNG. Два разных падения с одинаковой подписью — это не две логические ошибки, а что-то
системное, поэтому в #14 закрыты сразу оба подозреваемых:

- `scripts/apply_intro_disable.py` — `loadGL` выходит сразу, так что контекст `EAGLContext`,
  `GLKView` и таймер анимации не создаются вовсе. Интро — единственный потребитель OpenGL ES 2.0
  во всём приложении, так что этот путь просто исчезает.
- из `scripts/slim_ipa.sh` убран **`xcrun strip -x`** — единственный шаг, который перезаписывал
  бинарники после того, как сборка их создала и подписала, и при этом глушил ошибки через `|| true`.
  Замер показал, где он реально работал: `TelegramUIFramework` он не тронул вообще (51 594 символа
  против 51 593), зато срезал **129 КБ с `libswift_Concurrency.dylib`** — рантайма Swift Concurrency.
  Повреждённый рантайм роняет процесс там, где в этот момент исполняется Swift-код, то есть в разных
  местах каждый раз — ровно та картина, которую мы и видели.

Проверить, что фикс #4 действительно скомпилировался, по строкам в бинарнике нельзя: патч вставлен
**комментарием**, а комментарии компилятор выбрасывает. Настоящее доказательство — `work/textdiff.py`,
который сравнивает секцию кода `__TEXT,__text` двух сборок и считает ссылки на `GLKView`
(5 → 3: недостижимое тело `loadGL` выброшено).

### Как читать крашлог iPhone

Формат `.ips` легко читается неправильно. `EXC_BREAKPOINT` / `SIGTRAP` / `brk 1` / `pc 0x19dc544c0` в
первой половине файла — **не причина**: это поток `exc handler` (`termination.byProc`), который сам
выполняет `brk #1` уже после перехвата. Настоящая причина — в **`faultingThread`**:
`esr 0x82000007` = Instruction Abort, Translation fault, level 3, а `pc = far` — адрес, по которому
процесс попытался выполнить код и не нашёл там памяти. Плюс `procExitAbsTime − procStartAbsTime`
даёт время жизни процесса в наносекундах. Лог лежит в
«Настройки → Конфиденциальность и безопасность → Аналитика и улучшения → Данные аналитики».

## Что меняет патч

Ровно два файла:

**`submodules/TelegramCore/Sources/Network/Network.swift`**
- `seedAddressList` заменён на наш DC 2 → `2.27.200.203`
- порт `443` → `2398`
- убран `if testingEnvironment`, который уводил на тестовые ДЦ Telegram

Сид-лист — это только бутстрап: после первого `help.getConfig` сервер сам отдаёт клиенту свой

**`Telegram/BUILD`**
- `CFBundleDisplayName` / `CFBundleName` → `Xtreegram`
- URL-схемы `telegram` / `tg` / `tonsite` → `xtreegram` / `xtreegram-compat` / `xtreegram-site`

## Как собрать

1. Actions → **Build XTree Gram Unsigned IPA** → *Run workflow*.
2. Первая сборка идёт **60–90 минут** (Bazel тянет webrtc, tgcalls, td и компилирует их).
   Последующие — быстрее за счёт кэша Bazel.
3. По окончании скачать артефакт **`Xtreegram-unsigned-ipa-<N>`**.

Локально (нужен macOS + Xcode) то же самое делается так:

```sh
git clone https://github.com/TelegramMessenger/Telegram-iOS.git src
git -C src checkout 6ad963e5b62d354da79040f388ae2b9132fb17b8
git -C src submodule update --init --recursive
./scripts/apply_mods.sh "$PWD/src"
```

## Установка на iPhone

`.ipa` не подписан, поэтому:

1. Установить **Sideloadly** (или AltStore) на компьютер.
2. Подключить iPhone, перетащить `.ipa`, ввести обычный Apple ID.
3. На телефоне: *Настройки → Основные → VPN и управление устройством* → доверять профилю.

**Бесплатный Apple ID = подпись живёт 7 дней**, потом приложение надо переподписать. Платный
Developer Account (99 $/год) даёт год и не требует переподписки.

## Про минуты GitHub Actions

macOS-раннеры тарифицируются **×10**. Бесплатные 2000 минут/мес = **200 macOS-минут**,
а сборка съедает 60–90 — то есть 2–3 прогона в месяц. **Публичный репозиторий — безлимит.**
Секретов здесь нет: в патче только брендинг и адрес сервера, который и так известен по DNS.

## Обновление upstream

`UPSTREAM_REF` в workflow и патч жёстко связаны. При обновлении:

1. поднять `UPSTREAM_REF` до нового коммита,
2. локально прогнать `./scripts/apply_mods.sh <src>` — он скажет, если патч не ложится,
3. пересобрать патч под новый контекст (`git diff`), закоммитить оба изменения вместе.

## Что вырезано из `.ipa`

Расширения `Watch`, `Widget`, `BroadcastUpload`, `Share` и все локали кроме `Base, en, ru` —
чтобы архив был меньше и надёжнее подписывался бесплатным Apple ID. Список правится переменными
`IPA_DROP_PLUGINS` и `IPA_KEEP_LOCALES` в workflow.

Сборка только под **arm64** (реальные устройства). Для симулятора нужна отдельная конфигурация.
